# Exercise coverage by region and target

## Status and interpretation

This table covers every option in the current catalogue. It is a proposed course-content plan, not an implemented availability registry. No target course crate exists yet. Browser sample sessions provide a single-choice learning UI for three targets; translation and matching remain proposals. See [runtime environments](runtime.md) for sample availability.

The separate file-backed harness now seeds exercise availability for all 100 targets. See [experimental learning data](experimental-learning-data.md) for its profiles and teaching-stage selection; these mappings do not implement frontend exercises or target course content.

Country/region labels come from the catalogue and aid discovery. Availability is keyed by the exact target ID, never by country alone. A language can span countries, and a country can contain several language varieties and scripts. The shared source language is English.

Formats:

- **Choice**: [single choice](exercises/single-choice.md), using target content and one answer selection.
- **Translation**: [translate sentence](exercises/translate-sentence.md), both directions with typing and word bank.
- **Matching**: [match words](exercises/match-words.md), target words paired with English meanings.
- **Proposed**: candidate format requiring course content, validation, and UI before use.
- **Review**: English-source/English-target behavior needs a product decision; do not generate meaningless translation pairs.

## Target-specific adaptations

These are design proposals to be implemented in the target course definitions, not inferred automatically from region labels.

| Target scope | Proposed adaptation |
| --- | --- |
| `pt-BR` versus `pt-PT` | Keep vocabulary, spelling conventions, accepted translations, and generated content specific to the selected variety. |
| `zh-Hans-CN` versus `zh-Hant-TW` | Configure prompt and answer script independently from the interaction type. Chinese word-bank answers require an explicit segmentation and joining policy. |
| `yue-Hant-HK` | Treat it as its own target; do not substitute Mandarin vocabulary or curriculum labels. |
| `ja-JP` | Course content specifies permitted scripts, readings, segmentation, and accepted spelling forms. |
| Targets using right-to-left text | Supply text-direction metadata in the future course/UI contract; configure presentation and punctuation without reversing token identities. |
| Targets with meaningful diacritics | Keep search normalization separate from answer grading; preserve distinctions required by course rules. |
| Regional English targets | Resolve the intended learning goal before enabling English-to-English translation or matching; keep this decision separate from catalogue membership. |

## Availability policy

Future target crates should declare supported formats, script rules, word categories, vocabulary, and curriculum metadata. A session requests a format supported by its target course and the actual UI/core implementation. Missing content or an unsupported format must not silently select another variety.

Country does not determine the exercise classifier. Script-specific interactions such as tracing or handwriting can be proposed later, but require explicit content, rendering, and grading specifications before availability is declared.

When catalogue entries change, update this table so every target remains represented exactly once. This Markdown table is documentation; it is not runtime configuration. Add a validated availability registry when course implementations make one necessary.
