# Exercise specifications

Exercise type describes the interaction. Language variety, script, word category, and curriculum level are independent content constraints.

| Type | Learner action | Core status | UI status |
| --- | --- | --- | --- |
| [`single_choice`](single-choice.md) | Choose one answer card | Implemented with validation and grading | Planned |
| [`translate_sentence`](translate-sentence.md) | Translate by typing or assembling tokens | Proposed | Planned |
| [`match_words`](match-words.md) | Pair target words with English meanings | Proposed | Planned |

See [target coverage](../exercise-coverage.md) for proposed formats per catalogue region and language variety, [UI](../ui.md) for screen behavior, and [AI interaction](../ai-interaction.md) for generation requirements.

Each specification records purpose, required content, interaction, grading, validation, and current limitations. Extend these specifications alongside the corresponding core payload and UI. New types need their own document before being advertised as available.

Future possibilities such as listening, pronunciation, handwriting, and script recognition require separate content and grading designs. A writing system alone does not enable an exercise, and no country-specific format is automatically available.
